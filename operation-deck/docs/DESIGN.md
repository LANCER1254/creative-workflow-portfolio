# 設計とトレードオフ

## 構成

`index.html` に画面/CSS/モデル/イベント処理をまとめています。カードの読取モデル、ブラウザ内の作業メモ、手動工程の状態を別々に保持します。サンプルを読み込む操作で作業メモの受入やタスク完了を変更しません。

## 状態の意味

| 表示 | 意味 |
| --- | --- |
| 予約待機 | 予約の記録。実行可能と断定しない |
| 保留 | 理由の確認が必要。本人判断だけとは限らない |
| Done | ボード上の状態。本人受入・配備・保全は別 |
| 控え | 大型親案件。通常候補から分離 |
| 手動確認済み | このブラウザの工程メモ |

カテゴリーは複数に一致する場合があります。カテゴリー件数の合計とユニークカード数は同じではありません。元ID参照と実行依存も区別します。

## データ境界

公開用コピーでは実API取得処理と個人環境へのリンクを除去しています。コードに実カード・個人メモ・原稿・認証情報・GoogleドキュメントIDを含めません。JSON取込は利用者が選択したファイルをブラウザ内で読む操作です。localStorageキーも元ツールから分離しています。

入力値はtextContentなどのテキスト操作で表示し、タイトル/本文をHTMLとして挿入しません。JSON形式不正は現在の表示を保持して通知します。作業メモは別タブ更新を検出したら保存を止めます。localStorageの照合は分散トランザクションではなく、厳密な同時書込の保証や端末間同期はありません。

## 限界

単一HTMLは導入が簡単な一方、コード量が増えると保守性に限界があります。将来の分割では既存の状態契約と回帰試験を保持する必要があります。見た目の確認とブラウザ自動試験を、実業務全体の品質保証と同一視しません。
