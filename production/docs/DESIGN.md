# 課題と設計判断

制作中の「この場面をどう見せるか」「必要背景のどれが未確定か」「次に書く章はどれか」を別々の小さい体験に分けています。架空短編の3コマ・3背景・5章が入力です。効果の時間計測や採用実績は今回の検証対象に含めていません。

## 既存部分と今回の変更

| 領域 | 再利用 | 今回の限定変更 |
|---|---|---|
| 絵コンテ | モデル正規化、コマ編集・並べ替え、シート、JSON/HTML出力 | 合成初期値、デモ入口、埋込画像の検証、公開用キー |
| 背景 | 行編集、状態選択、画像表示、JSON読込・HTML出力 | 既存list/get/save契約をブラウザ内adapterへ接続、JSON書出し、競合・容量失敗表示 |
| 執筆 | Issue正規化、工程集計・絞込、関連プロット表示 | 合成入力、JSON復元入口、架空repository識別、GitHub/API非接続 |

ブラウザのES modulesとDOMを使い、配布物だけで静的HTTP起動できます。ビルドサービスやサーバDBを前提にしません。背景のadapterはfetchをグローバル置換せず、モジュール内からだけ呼びます。元コードのAPI形状に合わせた文字列は残りますが、HTTP要求にはなりません。

背景保存はlocalStorageの前回読取値と保存直前値を比較し、別タブ更新を検出したら上書きを拒否します。容量不足時も保存成功と表示しません。これはサーバトランザクションではなくブラウザ内の簡易競合検出です。

画像入力は2MB以内のPNG/JPEG/WebPを検証し、JSON内の外部画像参照を拒否します。文字列はDOMテキストかHTMLエスケープとして表示します。配布物に元ゲームの原稿やキャラ画像は含めず、コードで作成した幾何学PNGだけを使用します。

本人：課題定義・仕様判断・運用・採否。AI：既存コードの照合・切出し・限定改修・試験・文書化支援。元実装全体を今回新規開発した成果とは説明しません。
